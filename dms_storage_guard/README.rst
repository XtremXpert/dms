DMS can keep the content of its files in the database, in the Odoo
filestore or in existing attachments linked to a record. Only the
filestore is content-addressed: identical files share the same physical
file, while the database mode duplicates every copy in PostgreSQL and in
its backups.

This module adds a pre-installation guard: it refuses to install while a
DMS storage still keeps its files in the database, or while files are
waiting for a storage migration, and explains how to migrate them first.
Once installed, the same diagnosis is available from a dedicated screen.

Use Cases / Context
===================

The DMS addons can keep the content of a document in the database, in
the Odoo filestore or in existing attachments. The filestore is
content-addressed: identical contents are stored once, while the
database mode duplicates every copy in PostgreSQL and in its backups.

On a database that already holds documents, installing a storage-related
module without checking the storage mode hides silent costs: a larger
database, heavier backups, slower restores, and files whose storage type
no longer matches the storage configuration.

Installation
============

No external dependency.

The module refuses to install while a DMS storage keeps its files in the
database, or while files are waiting for a storage migration, and
explains how to migrate them first (Documents > Configuration > System >
Storages).

On a database that uses demo data, the check only logs a warning so the
module can still be installed for tests. To install anyway on another
database, set the system parameter
``dms_storage_guard.allow_database_storage`` to ``1``.

Configuration
=============

The check runs before the installation and blocks it when a storage
needs an action. It is bypassed automatically on a database that uses
demo data.

To install anyway on another database, set the system parameter
``dms_storage_guard.allow_database_storage`` to ``1``.

Usage
=====

Open *Documents > Configuration > System > Storage Check* to see the
state of every storage, the files waiting for a migration and the
remediation steps.

Known issues / Roadmap
======================

- Detect duplicated documents from their checksum and warn on upload.
- Report the space saved by the filestore deduplication, per storage.
- Add a maintenance action confirming the filestore integrity
  (attachments without a file on disk, files without an attachment).
